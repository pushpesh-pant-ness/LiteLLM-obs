# Build plan: from local stack to the target architecture

Target: see the architecture discussion (request path = Ingress -> LiteLLM x2 + Redis -> Egress proxy ->
providers; observability path = Gateway DB + replica -> reporting views, metrics store, OTel collector ->
per-team Grafana / Langfuse). Admin sees everything, an org sees its teams, a team sees only itself.

## Ground rules

- **No surprise downloads.** Phases 0-4 use only images already on this machine
  (`postgres:16`, `redis:7`, LiteLLM `main-stable`, `python:3.12-alpine`, current Grafana/Prometheus/
  Langfuse/ClickHouse). Phases 5-6 start only after security clears the images listed below.
- **Nothing breaks silently.** Phase 0 builds `scripts/verify.sh`; every later phase must pass it, plus
  its own new checks, before it is called done.
- **One phase = one reviewable change.** Each phase ends with a summary, evidence and your OK; with your
  approval it becomes one git commit, so any phase can be rolled back.
- **Data is backed up before risky steps** (from phase 1 on).

## The loop for every phase

1. **Design note** - what changes, which files, what "done" means. You approve or adjust.
2. **Build** - change config/code; data migrations only after a fresh backup.
3. **Verify** - `scripts/verify.sh` green + phase-specific tests (e.g. "team A cannot see team B").
4. **Show** - results and UI checks (Grafana, Langfuse, LiteLLM UI).
5. **Document** - README / NAMING.md / this file updated.
6. **Commit** (with your OK) -> next phase.

## Phases

| # | Phase | What gets built | Done when | Needs |
|---|---|---|---|---|
| 0 | **Safety net** | `git init`; `scripts/verify.sh` = alert unit tests + real-model smoke test + every Grafana query + Langfuse redaction marker test (prompt, answer, reasoning) + "team cannot see team" checks (filled in as phases add them) | One command proves the stack works; it catches each bug we hit this week | - |

| 3 | **Tenant access** | Grafana: one org per team and per LiteLLM org, each with its own scoped datasource + team dashboard (via API from bootstrap); Langfuse: one org + project per team (≈2 min manual UI step each), team callbacks send traces there; Alertmanager routes alerts to per-team Slack channels | Logged in as a team user you see only that team, as org lead only that org's teams, as admin everything - tested in Grafana and Langfuse | Slack webhooks per team (later) |
| 4 | **Gateway HA** | Dedicated Redis for LiteLLM; LiteLLM x2 sharing it; Prometheus discovers both instances; provider fallbacks behind each public model name | Kill one LiteLLM -> traffic continues; limits hold across both; a failing provider falls back | A 2nd provider key for fallbacks |
| 5 | **Edge** | TLS ingress (load-balances the 2 LiteLLMs, Grafana, Langfuse); egress forward proxy with provider allow-list; outbound internet blocked for every other container | Only allow-listed domains reachable; Netskope trust lives only on the egress proxy | Cleared images: reverse proxy + forward proxy |
| 6 | **Upgrades + telemetry** | Grafana 12.4.x, current Prometheus LTS + Alertmanager, ClickHouse 26.4, LiteLLM pinned release, Langfuse v4 (staged migration); OTel collector takes over redaction + per-team routing (plugin retired after parity test); Mimir as per-team metrics store (Prometheus remote-writes per tenant) -> teams get live dashboards | verify.sh green on new versions; redaction parity proven by marker test | Cleared images (list below); before Jan 2027 for Langfuse |
| 7 | **Identity + Enterprise** | LiteLLM licence: real orgs + org admins (bootstrap already supports), enforced log retention, SSO; Entra ID sign-in for Grafana + Langfuse with group -> org/team mapping; apps authenticate with Entra tokens (JWT) | Users land in the right org/team automatically from their Entra groups | LiteLLM licence key; IT: Entra app registrations, groups |
| - | **Production move** | Deploy the same compose (or k8s) on the shared server; internal registry with pinned digests; real object storage for Langfuse | Running on the server, verify.sh green there | IT: VM, DNS, TLS certificate |

Order rationale: 0-1 make everything after it safe; 2-3 deliver the admin / org / team visibility you asked
for; 4 adds resilience that matters most once real traffic arrives; 5-7 wait on security, IT and the licence,
so request those now in parallel.
